# 고객 원본 접수와 AI 검토

## 화면 구조
기존 프로젝트 헤더/탭/도구 모음/본문의 공통 grid를 유지한다. 생산 화면만의 높이 예외는 제거했다. 기존 탭 왼쪽, 고객 Data → AI Data Review → PBOM → TRR / 요구사항 → Process Readiness → 공정별 작업관리 오른쪽 순서다. 좁은 화면은 기존 가로 스크롤을 사용한다.

## 1. 고객 Data
원본 등록에서 여러 파일을 선택하거나 끌어다 놓으면 바로 접수한다. 자료명/문서유형 입력 없이 파일명을 사용한다. 파일별 처리 결과를 표시하고 최신 접수순 파일명/담당자/일시를 보여준다. 파일을 열면 기존 DocumentPreviewRenderer를 재사용한다. 다운로드 이력은 추가하지 않는다.
프로젝트 행 잠금 안에서 checksum으로 중복 확인하여 다른 이름의 동일 내용도 중복 제외한다. 같은 이름의 다른 내용은 새 원본으로 접수한다. 자동 Revision 확정/기존 원본 교체를 하지 않는다. 실패한 파일은 다시 선택하여 올릴 수 있다. 도중 화면 이동 시 아직 시작하지 않은 업로드는 멈춘다.

## 2. AI Data Review
문서 목록을 유지하고 행을 선택하면 기존 WorkPanel과 공유하는 WorkPanelFrame을 연다. 생산 분석은 승인된 50%/70% 폭, WBS/실적은 기존 560/760px를 사용한다. 문서 목록은 공통 행 44px/헤더 34px를 사용하고 썸네일은 34px 안에 표시한다.
패널 탭은 분석 요약/PBOM/TRR·요구사항/Process Readiness/공정별 작업관리/AI 대화이다. 이번 원본의 초안만 보여주고 항목 확정은 현재 영역의 선택 항목에 한정한다. 저장·확정은 상단에 배치하고 수정 버튼으로 편집칸을 연다.
썸네일/원본 팝업 버튼으로 별도 브라우저 창을 연다. 창 이동과 다른 문서 열기는 사용자가 직접 수행하며 창간 자동 동기화는 없다. 이미지/PDF/텍스트를 지원한다.
AI 대화는 기존 CommonAiChatPanel을 동일 패널의 AI 대화 탭에서 사용한다. 문서 비교 선택은 패널을 열기 전에 수행한다. 초안과 대화/확정 저장 API·권한은 기존과 같다.
이번 수정은 UI이며 TOP 품목 자동생성이나 구조화된 BOM 편집기 연결을 새로 추가하지 않는다.

## 3~6 확정 DATA
고객이 확정한 항목만 별도 테이블에 원본 근거/결정 버전/확정자/일시와 함께 저장한다. 기존 확정 이력은 보존한다. 동일 기준 원본·항목의 새 결정 버전이 확정되면 목록은 최신 결정을 표시한다. 신규 파일이 기존 원본의 Revision이라고 자동 간주하지 않는다.
이번 단계는 확정 항목 목록이며 기존 PART 마스터/BOM 편집기와의 연결, 정식 TR Report 출력, 실제 자재 재고/생산 실적 연결은 후속 작업이다. 내부 지식 7/8번 및 별도 공정 통합 뷰는 포함하지 않는다.

## 지원 형식/운영
기존 OPENAI_API_KEY/OPENAI_MODEL 설정을 사용한다. 별도 실행환경·패키지·모델 설치는 없다. 고객 파일은 사용자가 분석/대화 실행 시 기존 OpenAI 연결로 전송된다. 키 누락/지원 형식 오류/AI 실패는 명확히 표시하며 가짜 분석 결과나 파일명 대체 추론을 저장하지 않는다.
원본은 파일당 50MB까지 접수한다. AI 분석은 PDF/PNG/JPEG/WebP/텍스트, 파일당 12MB/선택 합계 30MB/최대 5개다. 브라우저 미리보기는 이미지/PDF/텍스트를 지원한다. Office/CAD 등은 원본 다운로드를 제공하며 분석 시 PDF 변환 접수를 안내한다. 원본 미리보기와 AI 분석 지원 범위는 업로드 허용 범위와 다르다.

## 반영
서버를 종료한 후 CS WIND 폴더에서 git pull cswind main → npm.cmd run db:migrate:cswind → npm.cmd run dev:cswind. 0009 마이그레이션은 검토/확정 테이블을 추가한다. 기존 DB 초기화/재복사는 하지 않는다.

## 검증
초안 유효성, 근거 원본 범위, AI 실패 시 저장 금지, 분석 시 확정 호출 금지, 파일만의 접수 및 중복 저장소 정리 단위 검증. 기존 127개 TypeScript 진단 대비 신규 진단 없음. Architecture/UI 검사 통과, DOM 감사 기존 P0=18/P1=11 유지.
작업 환경에는 실제 Z440 DB/API 키가 없으므로 실데이터 마이그레이션과 실제 모델 분석은 Z440에서 확인해야 한다. 브라우저 실행 파일 다운로드 연결이 타임아웃되어 실제 화면 QA는 이 환경에서 완료하지 못했다. 특히 동일 프로젝트의 목록/고객 Data/AI Data Review 탭 전환 시 헤더와 탭의 높이가 유지되는지, 좁은 화면의 분석 보기 전환을 현장에서 확인해야 한다.

## 2026-09-10 PBOM 구조화 변경 (위의 미구현 설명을 대체)
- 고객 Data 접수에서 Category A(BT/WT/IM/공통), Category B(초기/변경/누락 도면/부품 목록), A/B 공통을 구분한다. 분류 생략은 미분류로 저장한다. 출력 템플릿·예시는 별도 용도로 저장하며 기술 원본 분석 목록에서 제외한다.
- checksum 중복은 원본을 재생성하지 않는다. 다른 입력 분류로 같은 원본을 접수하면 공통으로 분류한다. 출력 예시를 입력 원본으로 자동 전환하지 않는다.
- 생산 프로젝트 생성 시 기존 `product_parts`에 TOP_ITEM을 만든다. 기존 프로젝트는 PBOM에서 TOP 품목 생성 버튼을 한 번 사용한다.
- TOP/ASSY/부품은 시스템 설정 → PART·BOM 기준정보의 Prefix/구분자/자리수/다음 번호를 공통 사용한다. 기본 예시는 P-000001, P-000002이며 Role, BOM Level, 고객 Revision과 독립적이다. 채번 이력은 기존 part_number_history에 기록한다.
- 고객 식별번호는 내부 품번과 별도 저장한다. PoC 자동 재사용 범위는 동일 프로젝트의 확정 고객 품목 매핑이다. 프로젝트 간 고객사·품목 정합성 판정은 하지 않는다. 구매품·공용품의 기존 마스터 선택은 기존 BOM 편집기에서 수행한다.
- PBOM 패널은 선택 문서 한 개의 계층 초안과 NEW/기존/확인 필요, 고객 Revision 변경 표시를 제공한다. 내부 품번은 확정 시 생성하며 신규 초안·재분석만으로 채번하지 않는다. 과거 텍스트형 초안은 재검증이 필요하다.
- 문서 최상위 ASSY를 프로젝트 TOP 바로 아래에 연결한다. 원본 ASSY/Part 구조·고객 번호·도면 번호·CompRev·Pos.·Section·수량·중량·근거를 저장한다. Level/경로/Section 총수량은 결정적으로 계산한다.
- 중량은 직접 추출값을 우선한다. 하위 전체 목록·수량·동일 중량 단위가 확인된 경우에만 합산한다. 미확인은 0으로 대체하지 않는다. 중량 단위 환산은 이번 범위에 포함하지 않는다.
- Parts List의 여러 Pos.가 같은 부품을 참조하면 개별 근거 행을 보관하고 기존 BOM 편집기의 Parent/Child 연결에는 수량을 집계한다. 같은 ASSY가 여러 경로에 재사용되어도 하위 1개당 수량을 중복 합산하지 않는다.
- 확정은 문서의 BOM 구조 전체에 적용한다. 기존 편집 잠금·순환 관계·누락 수량·서로 다른 ASSY 정의를 검사한다. 기존 확정에서 빠진 품목의 삭제, 다른 문서와 충돌하는 수량 변경은 자동 처리하지 않고 기존 편집기 검토를 요구한다.
- 확정 항목·품목 생성·BOM 연결·채번·이력은 동일 PostgreSQL 트랜잭션으로 처리한다. 실패 시 모두 롤백한다. 기존 bom_revisions 스냅샷에 고객 근거도 포함한다.
- 중앙 PBOM은 실제 product_bom_items 구조를 표시한다. 구매품/공용품 추가 버튼은 기존 PartBomWorkspace를 해당 TOP으로 연다. 편집기로 변경된 수량은 편집기 변경임을 표시한다.
- TRR/생산 준비/작업 정보는 검토 항목·요구조건/기준·원본 근거·검토 상태의 공통 표를 사용하고 행을 열어 상세 검토한다. 기존 4개 결과 영역과 공통 AI 대화 패널은 유지한다.
- 정식 TRR 템플릿 출력, 첨부 이미지 자동 배치, 전체 Category A/B 검수 완료를 의미하지 않는다.

### 적용/확인
CS WIND 서버를 종료한 후 `git pull cswind main`, `npm.cmd run db:migrate:cswind`, `npm.cmd run dev:cswind` 순서로 실행한다. 0010은 PBOM 연결/고객 품목 매핑/원본 분류를 추가하며 DB 재복사·초기화는 필요 없다.

시연 확인: 새 생산 프로젝트 생성 → TOP 채번 확인 → 고객 도면 접수 → AI 재검증 → PBOM 필수값 수정/초안 저장 → 전체 구조 확정 → 중앙 계층 확인 → BOM 편집기에서 구매품 추가/체크인 → PBOM 새로고침. 같은 분석 버전 재확정은 중복 품목을 만들지 않아야 한다.

검증: 수량 계층 계산, 직접/합산/미확인 중량, 기존 품목 식별, Revision 표시, 순환/잘못된 부모/상충 정보 거부, 공통 채번 포맷 및 기존 접수/검토 단위 검증. 실제 Z440 PostgreSQL/AI API 및 브라우저 상호작용은 이 작업 환경에서 검증하지 못했다. 전체 build는 기존 누락 파일 `build/sites-vite-plugin.ts`로 막혔으며 Node 설정의 production build도 기존 Cloudflare 플러그인 요구로 완료되지 않았다. 개발 스택/배포 설정은 변경하지 않았다.
