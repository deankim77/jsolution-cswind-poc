# TC800 생산 시연 시작

## 반영

CS WIND 개발 서버를 중지한 뒤 CS WIND 폴더에서 실행한다.

```powershell
cd C:\Projects\jsolution-cswind-poc
git pull cswind main
if ($LASTEXITCODE -eq 0) {
    npm.cmd run db:migrate:cswind
    if ($LASTEXITCODE -eq 0) { npm.cmd run dev:cswind }
}
```

DB 복사/초기화 스크립트는 다시 실행하지 않는다. 새 migration은 공정 자료 할당 테이블 하나와 조회 인덱스를 추가한다. 의존성과 실행 환경은 변경하지 않았다.

## 등록 순서

1. 관리자 로그인 → **새 프로젝트 → 생산용 프로젝트**.
2. **TC800 생산 템플릿 등록**. 프로젝트 템플릿 목록의 **생산용**에서도 동일 버튼을 사용할 수 있다.
3. **템플릿으로 T800 시연 프로젝트 만들기**. 시작일은 화면에서 선택한다. 기존 시연 프로젝트가 있으면 재사용하며 실적/자료를 덮어쓰지 않는다.
4. 프로젝트의 **일정·WBS → 생산 작업공간 → 전체 → 고객 Data**.
5. 사용자가 보관한 **TC800_POC_DATASET_V4.zip**을 선택한다. 최초 도면 24개, 고객 부품 목록 1개, 사양서 5개만 등록한다. 동일 파일의 재등록은 생략한다.
6. **AI Data Review**에서 파일명/ASSY 코드 매핑 제안을 확인한다. 공정/하위 ASSY를 선택하고 **할당 확정**한다.
7. 좌측 P2~P5 또는 하위 ASSY를 선택해 자료를 확인한다. 상위에 할당한 공통 자료는 하위 조회에도 표시한다.

## 현재 구현 범위

- 템플릿에 개발용/생산용 유형을 저장한다. 유형 없는 기존 템플릿은 개발용으로 조회한다. 복사/수정 시 유형과 기존 추가 메타데이터를 유지한다.
- 신규 생산 프로젝트는 PRD-YYYY-NNNN 코드를 회사/연도별로 발급한다. 기존 프로젝트 코드는 변경하지 않는다.
- TC800 템플릿: 6개 최상위 단계, 12개 Sub ASSY 요약, 실행 업무 67개, 산출물 계획 67개. 총 WBS 행 85개.
- 시작/종료 일정은 회사 근무일과 휴일에 맞춘다. P2~P5 및 Sub ASSY는 시연 가정에 따라 병행 배치한다. 실적은 0%이다.
- 템플릿/프로젝트/원본/할당은 실제 PostgreSQL 및 Storage Adapter로 저장한다. 자동 페이지 시드는 없다.
- ZIP의 파일 내용은 제공받은 V4 해시와 대조한다. 변경 패키지, 과거 지식, 검증 정답, 마스터 정답 워크북은 최초 접수에 넣지 않는다. 원본의 일반 이름이나 중복 그림도 임의 수정하지 않는다.
- 공정 할당은 PM/PL 또는 관리자만 확정한다. 완료 프로젝트는 변경할 수 없다. 공정 할당과 작업용 문서 승인은 구분한다.

## 아직 연결하지 않은 부분

AI 내용 분석, 구조화 PBOM 생성, TRR/요구사항 자동 추출, 변경 제안 승인 후 업무 데이터 적용, 자재 입고/검사 실적 연동은 미구현이다. 4개 영역은 원본/공정 연결 현황과 미처리 상태를 표시한다. 현재 분류는 파일명과 템플릿 기준의 규칙 매핑이며 AI 수행 결과로 표시하지 않는다.

신규 기본 템플릿은 P1 생산준비단계와 P6 FAT 및 출하를 사용한다. 일반 WBS 편집기의 단계 변경 잠금은 이번 단계에 추가하지 않았다.

## 검증

- Architecture / V2 UI Foundation 검사 통과.
- React DOM 감사의 기존 P0=18, P1=11을 늘리지 않음.
- 제공 V4 ZIP 실파일 읽기, 30개 원본 선별/정답 제외, 손상 ZIP 거부, 6단계 구조, 휴일/병행 일정 테스트 통과.
- Z440 PostgreSQL에 직접 접속하지 않았으므로 실제 DB 등록 및 브라우저 저장 흐름은 로컬 반영 후 확인 필요.
